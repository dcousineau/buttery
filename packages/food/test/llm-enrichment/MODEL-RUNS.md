# Model runs against this fixture set

Three candidate models, each run **3× over all 10 fixtures** (30 generations per
model), against the exact production prompt (`FALLBACK_PROMPT` +
`PROMPT_SLUG_LISTS`) and the exact production schema (`llmOutputSchema`), through
OpenRouter via `resolveProvider`.

The question asked was **only how the DECISIONS diverge** — confidence weights and
`note` wording were deliberately not scored.

- **gold** = the `expected` block in each fixture. Generated by Opus role-playing
  the classifier, one agent per recipe, **not human-reviewed**. Treat it as a
  reference point, not ground truth — see `README.md`.
- **agreed** = model emitted the same `(dimension, slug, verdict)` as gold.
- **contradicted** = model emitted the same `(dimension, slug)` with a DIFFERENT
  verdict. This is the number that matters.
- **gold-only** = gold said something, model was silent. Under sparse encoding
  silence is itself a verdict (`not_detected` / "not excluded"), so this is not
  free — it is the model declining to flag something gold flagged.
- **model-only** = model said something gold did not.
- **stable** = decisions identical across all 3 runs / distinct decisions seen.

## Findings that apply to every model

- **All 180 possible shape-diet judgments came back empty.** Across three models
  and 30 runs each, not one of `keto`, `low_carb`, `low_fat`, `low_calorie`,
  `diabetic`, `paleo` was ever emitted. The prompt's "only on clear, unambiguous
  cases, confidence ≤ 0.6" reads to every model as _don't_. Either the six slugs
  are dead weight in `LLM_ONLY_DIET_SLUGS`, or the instruction needs rewriting to
  say when to fire, not just when not to.
- **A fully-empty output validates.** Every field in `llmOutputSchema` has a
  default, so `{}` parses to "no allergens, no diet exclusions, no cuisine" — and
  the pipeline writes that as a successful enrichment. Observed twice in the qwen
  sweep (below). This is a merge-boundary hole independent of model choice.

## `mistralai/mistral-small-24b-instruct-2501`

Worst on every axis. 22 contradictions, and the direction is the problem:

**All 15 allergen contradictions ran in the LESS-cautious direction** — gold
`contains` → model `may_contain`, or gold `may_contain` → model `not_detected`.
The prompt says explicitly "when genuinely unsure, PREFER `may_contain`", and the
model consistently did the opposite. It also emitted 39 judgments with no
`ordinals` behind them, against a prompt line saying a judgment with no plausible
ordinal is worse than no judgment.

## `google/gemini-2.5-flash-lite`

Best agreement and by far the most stable (91/129 vs 71 and 73). 6 of 10 recipes
came back with zero contradictions across all 3 runs, vs 4/10 for mistral. Most
willing of the three to state an explicit `not_detected` (30 times) and the only
one that never contradicted gold on spice.

One dangerous failure class, on **Teriyaki Beef**: `wheat: not_detected` +
`gluten: not_detected` + `gluten_free: likely`, on 2 of 3 runs, with ½ cup soy
sauce in the ingredient list. That is a `likely` verdict that reaches the UI — the
recipe-tags layer surfaces `likely` and drops everything else — for a dish that
is not gluten free. The pattern is packaged condiments: the model reads "soy
sauce" as a soy product and stops.

### The two 0-stable recipes are not judgment drift

**Chocolate Chip Cookies run 2 and Tamate Ka Kut run 3 returned completely empty
output** — `allergens: []`, `diets: []`, `cuisine: []`, `mealType: []`,
`spiceLevel: null` — while the other two runs of each were normal and correct.
That single empty run is what drove those recipes to 0 stable, not disagreement.

The pipeline would write that empty result as a successful enrichment: a cookie
recipe with eggs, butter and wheat flour recorded as detecting no allergens and
excluded from no diet. Neither mistral nor gemini produced a single empty run in 60. Qwen also produced 5 runs with zero allergens and 2 with zero diets (mistral
and gemini: 0 and 0).

## Outcome

**`google/gemini-2.5-flash-lite` is the chosen model.** It is what
`services/pipeline/.env.example` ships and what `LLM_ENRICHMENT_MODEL` is set to.

`deepseek/deepseek-v4-flash-0731` was started as a fourth candidate and
**cancelled at 20 of 30 runs** once gemini was picked — its partial numbers are
not reported here because a partial sweep cannot be compared against three
complete ones.

## Reading

`gemini-2.5-flash-lite` is the recommendation. It leads on agreement and stability,
and its one bad failure class is addressable in the prompt.

`qwen3.7-flash` ties gemini on agreement and beats it badly on contradictions
(2 vs 19) and evidence discipline (6 vs 15 ordinal-less judgments), but it is the
only model that silently returns nothing, and it needs 4× the token budget to
return anything at all. Cost per run is materially worse.

`mistral-small-24b` should not ship: its errors are systematically in the
under-warning direction on allergens.

Two changes identified against the chosen model — the first is done, the second
is knowingly deferred:

1. ~~**Reject a fully-empty model output at the merge boundary** rather than
   writing it as a successful enrichment.~~ **Done** — `isEmptyLlmOutput` in
   `@buttery/food/llm/schema.ts`, thrown on by `runLlmEnrich` before the merge.
   The recipe goes to `llm_status='error'` and BullMQ retries it, because the
   runs either side of an observed empty one came back correct.
2. **Add a prompt line about packaged sauces and condiments** hiding wheat, soy
   and dairy (soy sauce, oyster sauce, stock cubes, curry paste), then re-run.
   **Deferred, accepted** — gemini ships with the Teriyaki `gluten_free: likely`
   miss known and unfixed, to be picked up in a later prompt-refinement pass.
   It stays the highest-severity finding in this file: a `likely` diet verdict
   is the one thing that reaches the UI (`recipe-tags.ts` surfaces `likely` and
   drops `excluded`/`unknown`), so this failure mode is user-visible in a way
   none of the others are. Re-run this fixture set when that pass happens.

## Reproducing

Prompts were rendered with the production CLI:

```
pnpm --filter @buttery/pipeline prompt <recipeId...> --json
```

Model calls used `resolveProvider` + `generateText` + `Output.object({ schema:
llmOutputSchema })`, with `LLM_ENRICHMENT_PROVIDER=openrouter` and
`LLM_ENRICHMENT_MODEL` set per sweep. Raw per-run outputs were not committed —
they are ~90 JSON blobs of model prose, regenerable, and would rot the moment the
prompt changes.
